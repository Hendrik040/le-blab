# Le Blab audit: efficiency, bugs and cleanup

**Status:** the two High bugs and the reconnect bug (Medium) are fixed, with regression tests, in `5ffcafd` and `596f17b`. Everything else is as found on 2026-11-02.

## 1. Snapshot

- **What it is:** a native macOS push-to-talk dictation app (a Wispr Flow clone). It is built with Swift and SwiftPM, with no Xcode project, and is about **10k lines of code** across 3 commits.
- **How dictation works:**
  - Hold the hotkey and audio is captured at 16 kHz.
  - Audio streams to Voxtral 3 over a realtime WebSocket. Replay and batch transcription are the fallbacks, and there is an optional accuracy mode.
  - Mistral Small 4 formats the text when needed, sometimes starting before you release the key ("speculative" formatting).
  - Text goes in at the cursor through Accessibility, clipboard paste, or simulated typing.
- **Measured latency:** about **0.55 s from key release to text**. Most of the gain comes from "early finalization", which inserts text once the stream looks settled instead of waiting for the server's final `done`. That shortcut is also the riskiest part (see Bugs).
- **Idle cost is close to zero:**
  - No WebSocket stays open between dictations.
  - The audio engine is prepared but the mic is not running.
  - Timers are cancelled when not needed.
  - The hotkey listener runs on its own thread.
- **UI:** a menu-bar duck, a recording overlay, an always-on bubble with a right-click menu, Settings and Onboarding windows, and an opt-in History.
- **Tooling:**
  - A seeded, statistically sound benchmark that drives TextEdit and compares against Wispr.
  - `leblab-probe`, a command-line tool that runs the real pipeline against the live API.
  - **109 tests**, with good fakes for the pipeline.
- **Where it's weak:**
  - Timing races in the release and finalize paths.
  - Wasted LLM calls.
  - Too much UI redrawing while recording.
  - The insertion, audio and hotkey code has no tests.

## 2. Top efficiency opportunities

Ranked by impact for the effort.

1. **Stop wasted formatting calls (Mistral Small).** Effort **S–M**.
   - **Where:** `DictationController.swift:264`, `:453`, `:300`; `SpeculativeFormatting.swift:34`.
   - **What happens today:**
     - At release, a speculative formatting request always fires, even in paste-first apps (Chrome, Slack, VS Code, Electron). With "speed-first" on (the default), that answer is always thrown away.
     - Speculative requests are never cancelled: not when they're pushed out of the 3-slot cache, not when they don't match, not on Escape, and not in speed-first mode.
   - **Fix:** decide paste-first from the frontmost app's bundle ID before speculating, and skip it there. Add `cancelAll(except:)` and call it from the cancel, completion and eviction paths. Allow only one pause-time request in flight at a time.
   - **Gain:** **one wasted chat completion per dictation in paste apps**, plus several on long dictations with pauses. Saves tokens, rate-limit headroom and battery (fewer network wake-ups).

2. **Cut UI redrawing while recording.** Effort **S**.
   - **Where:** `LeBlabApp.swift:9`, `DictationController.swift:182`, `DuckViews.swift:147`, `OverlayController.swift:67,88`, `BubbleController.swift:68`, `MenuBarContent.swift:74`, `DuckViews.swift:109`.
   - **What happens today:**
     - The audio level is published about 20 times a second, and every transcript update is published too. Both re-render the whole menu-bar scene and rebuild the menu-bar icon image each time.
     - Every transcript update calls `setFrame(display:true)` on the overlay and runs a spring animation.
     - The bubble keeps updating its level meter while it is hidden.
     - The overlay publishes the level twice per audio chunk.
     - Rendering the menu re-lists all CoreAudio devices (unverified whether this runs while the menu is closed).
   - **Fix:**
     - Move `level` into a small separate observable object.
     - Have the scene observe only a derived "is recording / needs attention" value.
     - Cache the two menu-bar images.
     - Resize and animate the overlay only when the state type changes, not on new text.
     - Gate the bubble's meter on the overlay being hidden.
     - Cache the microphone name.
   - **Gain:** **removes 20–60+ main-thread invalidations per second** during capture, which is the window where latency matters.

3. **Cache the duck sprite and pause it when it isn't moving.** Effort **M**.
   - **Where:** `DuckViews.swift:57`, `OverlayController.swift:184`.
   - **What happens today:** each frame re-draws a 36x32 sprite with about 600 Canvas fills. It runs at 20 fps plus every level or text update, so **about 40–60 renders a second**. It also keeps running during up to 12 s of static error or "not inserted" states, and in Onboarding.
   - **Fix:** cache rendered frames as a `CGImage` keyed by a normalized pose (frame number mod 60, level rounded to 4 steps). Pause the timeline in `.failed`, and use a slow blink-only schedule in idle and hint states.
   - **Gain:** steady CPU/GPU savings whenever the overlay is visible.

4. **Make paste-app insertion cheap.** Effort **S**.
   - **Where:** `TextInsertionService.swift:183`, `:122`, `:430`, `:439`.
   - **What happens today:**
     - In paste apps, the focused element is looked up twice per dictation, once by `insertProvisional` and again by `insert`.
     - Each lookup walks up to 12 ancestor elements, 2 Accessibility calls per level.
     - That adds up to **about 50 blocking cross-process calls on the main thread before every ⌘V**.
     - The character count is re-read many times, and an Accessibility write still waits for the previous clipboard restore (up to 500 ms).
   - **Fix:**
     - Reject paste-first apps by bundle ID before any Accessibility lookup.
     - Compute "is inside a web page" (`isInsideWebArea`) only when needed.
     - Resolve the focused element once and pass it through.
     - Read the field state once per operation.
     - Wait for the pending restore (`pendingRestore`) only inside `paste()`.
   - **Gain:** a direct cut to release-to-text time in Chrome, Slack and VS Code. Chromium builds its Accessibility tree lazily, so these calls can be slow there.

5. **Narrow the formatting router's trigger words.** Effort **M**.
   - **Where:** `FormattingRouter.swift:50`.
   - **What happens today:** single common words send the text to the LLM, for example "doch", "nein", "Punkt", "sorry", "actually", "dot" and "dash". **A large share of German dictations pays a 0.4–1.5 s LLM round trip** for no change in the output.
   - **Fix:** log the routing reason. Measure how often the LLM output equals local cleanup's output, per reason. Narrow the triggers to phrase-level patterns.
   - **Gain:** fewer LLM calls and faster text for ordinary sentences.

6. **Fix early finalization and schedule it instead of polling.** Effort **S**.
   - **Where:** `TranscriptionSession.swift:293`, `:310`.
   - **What happens today:** settle detection polls every 25 ms and runs a regex over the whole text each tick.
   - **Fix:** sleep until `max(releasedAt+lookAhead, lastPostFlushDelta+settleWindow)`. Bundle this with the truncation fix in Bugs #1.
   - **Gain:** removes 0–25 ms of rounding on the critical path. The fix also finalizes sooner when flush text arrives early (~250 ms).

7. **Faster recovery on a bad network.** Effort **M**.
   - **Where:** `TranscriptionSession.swift:273`, `:167`; `VoxtralBatchClient.swift:15`.
   - **What happens today:**
     - A 429 (rate limited) triggers 2 immediate reconnects and ignores `Retry-After`.
     - A stalled stream waits **6–16 s** before the batch fallback starts.
     - In accuracy mode, a hung batch upload costs up to **30 s** even though usable realtime text is already in hand.
   - **Fix:** back off on 429. Add a "no text 1.5 s after flush" watchdog that starts batch in parallel. Race the accuracy batch against the realtime result with a tight timeout.
   - **Gain:** multi-second savings in exactly the situations users notice most.

8. **Keep the mic engine warm in all cases.** Effort **S**.
   - **Where:** `AudioCaptureManager.swift:76`, `:116`, `:75`; `AppCoordinator.swift:145`.
   - **What happens today:**
     - The prepared engine is discarded on any device change and never rebuilt.
     - It isn't re-prepared after a mic change in Settings or after the mic permission is granted, so the next press pays the cold start (~44 ms instead of ~12 ms).
     - The rebuild after each dictation runs on main about 0.3–0.5 s after release, which overlaps the insert window (unverified).
     - With the system default mic, the prepared engine may stay bound to a stale device (unverified).
   - **Fix:** reuse the stopped engine instead of rebuilding it, or rebuild only after insertion. Re-prepare when the device or permission changes. Listen for `kAudioHardwarePropertyDefaultInputDevice` changes.

9. **Move Accessibility and audio encoding off the main thread.** Effort **M**.
   - **Where:** `TextInsertionService.swift:472`, `VoxtralRealtimeProtocol.swift:30`.
   - **What happens today:**
     - Accessibility writes busy-wait with `usleep` for up to 250 ms on main.
     - Each audio chunk goes through `JSONSerialization` with sorted keys, base64 and socket sends, all on main.
     - A replay encodes the whole recording in one main-thread turn.
   - **Fix:** use a serial actor for Accessibility work and for building and sending socket frames. Build the audio frame with string interpolation (base64 needs no JSON escaping).
   - **Gain:** less UI stutter, and audio no longer arrives in bursts when main is busy. The per-chunk CPU cost itself is small.

10. **Connect the WebSocket earlier** (unverified). Effort **M**.
    - **Where:** `MistralAPI.swift:81`; `AppCoordinator.swift:269`.
    - **What happens today:** each dictation opens a fresh socket, which takes 250–370 ms. The HTTPS warm-up fires late, and the WebSocket upgrade can't reuse it.
    - **Fix:** start the socket on the earliest signal (modifier-down for chord hotkeys), or keep one pre-connected socket for about 30–60 s after use. Re-warm the HTTPS connection before the formatting call on long dictations.
    - **Gain:** up to 300 ms on short holds. **Measure release-to-final for holds under 1 s first.**

**Quick wins (S, low impact each):**
- Have `PermissionsManager.refresh()` publish only when a value changes (`:24`). Today it runs on every press and once a second while polling.
- Cache the ⌘V key code (`KeyCombo.swift:182`).
- Cache `VocabularyCorrector` instead of rebuilding it on every press (`AppCoordinator.swift:255`).
- Track lengths incrementally in `displayText` instead of O(n) work per update (`TranscriptionSession.swift:23`).
- Reuse the converter's output buffer, use vDSP for the level meter, and measure the level on the converted mono audio (`AudioCaptureManager.swift:194,217`).
- Check the real audio buffer size, which may be ~100 ms rather than 50 ms, and re-tune the release tail and in-flight wait to match (unverified, `:152`).
- Move vocabulary out of the system prompt so the prompt and examples stay cacheable (unverified benefit).
- Write History to disk off main (`HistoryStore.swift:75`).
- Cache the launch-at-login status instead of querying it during render (`AppCoordinator.swift:307`).
- Lower the benchmark's 5 ms TextEdit polling, which may skew its own measurements (unverified).

## 3. Bugs and risks

**High**
- **Early finalization can cut off the last words.** `TranscriptionSession.swift:310`
  - It accepts text streamed before release that ends in punctuation, without waiting for any text after the flush.
  - Example: you say "Sounds good. See you then" and only **"Sounds good." is inserted**.
  - The later `done` mismatch is only logged.
  - **Fix:** require at least one text update after the flush, or cap the wait at ~450–500 ms.
- **A quick re-press kills the new recording.** `DictationController.swift:266/275`, `AudioCaptureManager.swift:210`
  - The previous dictation's delayed `audio.stop()` fires 0.1–0.22 s after release and **stops the new engine**, so the second dictation gets no audio.
  - The old wait also eats the new recording's first audio chunk, and chunks already queued by the old engine land in the new session.
  - This is reachable in hold mode, not only toggle.
  - **Fix:** give each recording a generation number or token, and ignore stale stops and stale chunks.

**Medium**
- **After a reconnect, early finalization can insert only the first sentence.** `TranscriptionSession.swift:224`. The replay path doesn't reset its timing, so a partial replay can finalize. Disable early finalization after any reconnect.
- **History older than 30 days is deleted on every launch.** `AppCoordinator.swift:59` (cleanup at `HistoryStore.swift:62`).
  - Old entries are pruned with the default 30-day setting before your setting loads.
  - The trimmed list is written back on the next append.
  - Anyone with retention set above 30 days loses data.
- **Text can be inserted twice by `replaceProvisional`.** `TextInsertionService.swift:247`. It detects that the polished text was added in front of the draft instead of replacing it, logs the error, and still returns `.replaced`, leaving **both copies** in the field.
- **An unconfirmed Accessibility write falls back to paste.** `TextInsertionService.swift:160`. That is the opposite of the provisional path's no-reinsert rule, so text can be **inserted twice** in apps that apply edits late. It is reachable in the default config for short or clean text in native apps.
- **Any 400 permanently turns off `reasoning_effort=none`.** `TranscriptFormatter.swift:263`. 400, 422 and 404 are all treated as "this model rejects `reasoning_effort`", which slows formatting for the rest of the session and costs an extra round trip each time.
- **The 429 reconnect ignores `Retry-After`.** `TranscriptionSession.swift:273`. It uses up its reconnects, then falls back to batch, which is also rate-limited.
- **The level detector's noise baseline can break silence detection** (unverified). `AudioCaptureManager.swift:241`. If the first buffer is digital silence, the baseline seeds at -160 dB. In rooms louder than -50 dB, every chunk then counts as voice, so the release tail is never skipped and pause speculation never fires.
- **Early-finalization mismatches can't be seen in production.** `DictationController.swift:164`. `onLateVerification`, `finalizedEarly` and `requestID` are only used by the probe, so truncated inserts look like successful dictations.
- **The benchmark scripts read the legacy Keychain item `local.murmur.Murmur`.** `scripts/benchmark.sh:85`, `run-benchmark.sh:17`. The result is either a Keychain prompt that steals focus mid-run, or a stale key.
- **The e2e clipboard check can pass without running.** `scripts/e2e-selftest.sh:43`. Nothing builds `.build/pbhash`, so both hashes come back empty and the check reports "unchanged".
- **A stale timeout in `waitForFn` resolves a later trial.** `BenchHarness.swift:744`. In human-Fn mode this produces spurious gate timeouts or wrong release timestamps.

**Low**
- **Blind paste reports success.** `TextInsertionService.swift:168`. When nothing has focus, it pastes anyway and reports "inserted".
- **Retry is offered for errors that can't succeed (401, 403, 400).** `TranscriptionSession.swift:197`. The audio is also kept in memory longer than needed.
- **A second failed dictation drops the first one's audio without zeroing it.** `DictationController.swift:366`.
- **Zeroing the audio buffer may zero a copy** instead of the original bytes, and the WAV data and per-chunk buffers are never zeroed (unverified). `VoxtralBatchClient.swift:37`, `TranscriptionSession.swift:374`.
- **The formatter's output check lets short wrong answers through.** `TranscriptFormatter.swift:168`. Example: "Paris." inserted in place of a 5-word question.
- **The model name shown in diagnostics comes from current settings,** not from the model that produced the text. `DictationController.swift:353`, `TranscriptionSession.swift:202`.
- **Typing mode can split emoji** across key events. `TextInsertionService.swift:358`.
- **Possible thread-safety issue** (data race) with the audio converter and the level detector between the audio thread and main (unverified). `AudioCaptureManager.swift:190`.
- **The level meter reads only channel 0** (unverified). `AudioCaptureManager.swift:217`. On USB interfaces with the mic on input 2+, the meter stays flat and the level detector reports silence.
- **An audio-device change mid-dictation leaks a notification observer.** `AudioCaptureManager.swift:156`.
- **A lost key-up needs one extra press to recover** (unverified). `HotkeyManager.swift:164`.
- **Accessibility being revoked goes unnoticed** while the app is in the background (unverified). `PermissionsManager.swift:62`.
- **The menu-bar warning icon doesn't update on mic permission changes.** `LeBlabApp.swift:20`.
- **"Reset to defaults" writes every default back to disk** and leaves `hasCompletedOnboarding` inconsistent between memory and disk. `SettingsStore.swift:106`.
- **Activating the hotkey can register it twice** when Accessibility changes. `AppCoordinator.swift:181`.
- **The mic-start benchmark's later "cold" runs are actually warm.** `MicStartProbe.swift:23`. The documented 44→12 ms gain is unreliable.
- **Benchmark preflight requires the mic name to contain "MacBook".** `BenchHarness.swift:822`. It fails on a Studio, mini or iMac.
- **The scripts pass the API key as a command-line argument** (`open --env`), where other processes of the same user can read it. `e2e-selftest.sh:52`.

## 4. Cleanup

- **`complete()` is about 150 lines** with 3 insertion paths and duplicated label logic (`DictationController.swift:347`). Extract an `InsertionStrategy` and one `finish(outcome:)` helper.
- **Dead code:**
  - `insertViaAccessibility` (`TextInsertionService.swift:482`) and a duplicated doc comment.
  - `requestID`, `StreamingTranscriber.displayName`, and the parsed-then-dropped `.segment` and `turnEnd` reason fields.
  - The discarded `tile` in `AssetRenderer.swift:21`.
  - A launch check for `keyState == .missing` that is always false.
  - An `audio-missing` status that is never produced.
- **Duplication:**
  - `run-benchmark.sh` vs `benchmark.sh`.
  - `PixelBars` vs the bubble's meter.
  - `provisionalText` and routing run 4–6 times per dictation.
- **Shipping app carries the benchmark:** about 1,070 lines of harness (key injector, event tap) plus `WordErrorRate` in LeBlabCore. Move them to a `leblab-bench` target.
- **Build:**
  - The binary is **unstripped (3.1 MB; 1.49 MB stripped)**. Gain is bundle size only.
  - Signing defaults to ad-hoc, which resets permissions on every rebuild. Default to "ClaudeSessionMonitor Developer" or warn loudly.
  - The version is hard-coded to 1.0.0. Stamp the git SHA into it.
- **Docs out of date:**
  - The settle window is documented as 150 ms; the code uses 100 ms.
  - The streaming delay is documented as "480 ms default"; the code uses 240.
  - The tail-skip threshold is documented as 150 ms; the code uses 300 ms.
  - The latency table was measured at 480 ms.
  - Paths say `Sources/Le Blab/`, and the docs mention a non-existent `VoxtralStreamingClient`.
  - The README says "77 tests"; there are 109.
  - The manual checklist's latency targets of 1.2 s / 0.7 s are stale.
- **Probe defaults don't match the app:** 480 ms delay, `finalTimeout` 4, and it always uses the tracing socket. Align them with the app.

## 5. Test gaps

- **Both high-severity races pass the current suite.** Missing tests:
  - punctuated text before release plus more text 400 ms after the flush;
  - press, release, press within 50 ms (FakeAudio's stop is synchronous, so it can't model this);
  - a reconnect while finalizing;
  - 429 backoff;
  - the exact `input_audio.append` wire format.
- **No tests at all for** `TextInsertionService`, `AudioCaptureManager`, `HotkeyManager` (key, chord and Escape state machine) or the `reasoning_effort` retry. Also none for cancelling evicted speculative requests.
- **The app layer is untested:** the coordinator, overlay and window wiring, history retention ordering, `resetToDefaults`, and whether `refresh()` publishes.
- **The benchmark statistics live in the executable target,** so they can't be tested. Move them to a small library.
- **Many tests rely on wall-clock sleeps on the main actor** and no suite runs serialized, so they can flake on a loaded machine (unverified). Inject a clock.

## 6. Strengths to keep

- **Audio is queued before `session.created`**, so connecting overlaps speech and no first words are lost.
- **The final transcript comes verbatim from `transcription.done`**, which avoids duplicated words.
- **Insertion order is reserved when you release (synchronous `OneShotGate` chain)**, so overlapping dictations always insert in order.
- **Recovery is layered:** reconnect and replay, then batch, then Retry with the audio kept. A 401 short-circuits straight to failure.
- **Idle cost is near zero** (see Snapshot), and the hotkey listener runs on its own thread and recovers if macOS disables it.
- **The formatter is tuned for latency:** temperature 0, predicted outputs, `reasoning_effort=none`, a cache key, one shared HTTP/2 session, and a local fallback for every failure.
- **The clipboard is handled carefully:** transient and concealed markers, restore only if the clipboard is unchanged, and full ⌘V chords with a wait for modifier keys to release.
- **The pipeline is fully fakeable:** `RealtimeSocket` and the transcriber protocols make it testable without the network.
- **The benchmark design is sound:** seeded and blocked, with a Hodges-Lehmann estimate and a seeded bootstrap.

## 7. Suggested order of work

1. **Fix correctness first (S–M, about 1–2 days).**
   - Early-finalization truncation, plus a deadline-based settle check.
   - Disable early finalization after a reconnect.
   - Re-press race (generation tokens).
   - History retention data loss.
   - The two duplicate-insert paths.
   - 400 misclassification.
   - Wire `finalizedEarly`, the late `done` check and `requestID` into diagnostics.
   - Write regression tests for each fix.
2. **Stop wasted network work (S).**
   - Skip speculation in paste apps; cancel unused speculative requests on completion, Escape and eviction.
   - 429 backoff and `Retry-After`; a stall watchdog with batch running in parallel; a tighter accuracy batch timeout.
   - Log routing reasons, then narrow the router's trigger words.
3. **Lighten the main thread (S–M).**
   - Narrow what the UI observes (separate level object, cached menu-bar images, overlay resize only on state change).
   - Cache and pause the duck sprite.
   - One Accessibility lookup per insert, with bundle ID checked first.
   - Mic prewarm fixes.
   - The quick wins from §2.
4. **Structural latency work (M, measure first).**
   - Move Accessibility and socket encoding off main.
   - Pre-connect the WebSocket.
   - Check the real audio buffer size and re-tune the release tail and in-flight wait.
   - Re-run `leblab-probe` at 240 ms with the release → last-update timing recorded.
5. **Hygiene (S–M).**
   - Fix the benchmark scripts' Keychain lookup and the pbhash build.
   - Move the harness into its own target.
   - Strip the release binary.
   - Default to the local signing identity.
   - Update the docs.
   - Add tests for insertion, hotkeys and audio.
   - Make timing tests clock-injected.
